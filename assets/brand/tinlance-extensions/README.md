# Tinlance Extensions brand assets

The canonical visual identity is supplied in the Tinlance Extensions logo kit (version 1.0, November 2026). The source files in this directory are copied from that kit; do not redraw or approximate the mark.

## Core tokens

| Token | Value | Use |
|---|---|---|
| Ink | `#0A0C0B` | Primary dark surfaces and dark tile |
| Lime | `#C6FF4A` | Primary accent and light tile |
| Paper | `#F4F4F0` | Light surfaces and primary text on ink |
| Mute | `#5B625D` | Secondary text |

## Mark rules

- The primary mark is the three-node T with an open terminal ring. The ring is the extension dock/connection point and must remain open.
- The ink tile is the default icon treatment. Use the lime tile for dark-page contexts where the ink tile would disappear.
- Use the simplified small mark at 32 px and below; use the regular mark at 48 px and above.
- Keep at least one quarter of the tile width clear on every side.
- Do not recolour, add gradients or shadows, stretch, rotate, or fill the terminal ring.
- Use the black mark on paper/light surfaces and the white mark on dark surfaces where a standalone mark is required.
- The square and diamond port shapes are labelled proposed variants in the supplied guide. They are not the default corporate mark and must not be used as the suite-wide logo without a separate owner decision.

## Files

- `icon-ink.svg`, `icon-lime.svg`: standard app marks.
- `icon-small-ink.svg`, `icon-small-lime.svg`: simplified small-size variants.
- `variants/`: proposed port-shape explorations only.

The supplied ZIP also includes approved PNG sizes, dark/light lockups, browser-store icon and promotional artwork. Preserve those source PNGs when preparing store submissions; do not recreate them from screenshots. The one-page usage sheet is included in the original logo kit supplied with the project.

## Product UI direction

Use a restrained, high-contrast, security-oriented interface: Ink as the structural base, Paper for readable content surfaces, Lime for primary actions/focus/selected states, and Mute for secondary labels. Avoid using Lime for long body copy. Maintain accessible contrast and visible keyboard focus; validate each actual foreground/background pair rather than relying on the palette names alone.

Brand consistency does not override browser-store requirements, accessibility, or product-specific usability. Extension permission prompts and browser-owned UI must remain native and unaltered.
